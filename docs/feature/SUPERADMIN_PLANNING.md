# План реализации (Фаза 3: Planning) — Superadmin (клиент)

**Дата:** 2026-09-17  
**Статус:** План готов к ревью

В соответствии с архитектурным решением (`SUPERADMIN_DESIGN.md`) и методологией проекта (`development-process.md`), реализация разделена на последовательные, независимые и проверяемые этапы. Каждый этап завершается отдельным коммитом и прохождением Quality Gates (линтеры, тесты, проверка типов).

---

## Этап 1: Инфраструктура HTTP-клиента и хранилища токенов

**Цель:** Подготовить базовый транспорт и хранилище для независимой административной сессии.
**Задачи:**

1. `src/features/auth/tokenStorage.ts`: Модифицировать функции хранилища для поддержки второго типа токена (namespace `'user' | 'admin'`), сохраняя обратную совместимость.
2. `src/lib/http/client.ts`:
   - Ввести `adminAuthToken` и экспортировать `setAdminAuthToken`.
   - Добавить логику маршрутизации токенов: для путей, начинающихся с `/admin/`, использовать `adminAuthToken`, для остальных — `userAuthToken`.
   - Реализовать и экспортировать методы `patch`, `put`, `delete`.
   - Добавить пропуск сериализации и заголовка `Content-Type`, если `body instanceof FormData`.
   - Извлечь поле `code` из тела ответа сервера при ошибках и пробросить его в класс `HttpError`.
     **Критерии приемки:** Код компилируется без ошибок TypeScript. Линтер проходит. Пользовательское приложение собирается и авторизация обычных юзеров работает как прежде (регрессия отсутствует).

---

## Этап 2: Redux-состояние суперадмина

**Цель:** Реализовать глобальное управление состоянием для сессии суперадмина.
**Задачи:**

1. `src/features/superadmin/adminAuthSlice.ts`:
   - Создать структуру состояния: `{ status, admin, error }`.
   - Написать Thunks: `bootstrapAdmin`, `loginAdmin`, `logoutAdmin`, `changeAdminPassword`.
2. `src/app/store.ts`: Подключить `adminAuthSlice` к `rootReducer`.
3. `src/App.tsx`: Добавить параллельный вызов `dispatch(bootstrapAdmin())` рядом с инициализацией пользовательского приложения.
   **Критерии приемки:** В Redux DevTools появляется корректный слайс `adminAuth`. При старте приложения уходит сетевой запрос `GET /admin/me` для восстановления сессии суперадмина.

---

## Этап 3: Маршрутизация и каркас административной панели

**Цель:** Создать защищенную зону маршрутов для UI администратора.
**Задачи:**

1. Создать компоненты-охранники `RequireAdminAuth.tsx` и `RequireAdminGuest.tsx`.
2. Создать компонент `AdminLayout.tsx` (оболочка с темной шапкой и навигацией для администратора).
3. `src/App.tsx`: Настроить новые маршруты:
   - `/admin/login` (открытый для гостей админ-зоны).
   - `/admin` (защищенный, с редиректом на `/admin/superadmins`).
   - `/admin/superadmins`, `/admin/me` (пустышки на данном этапе).
4. `src/features/auth/pages/LoginPage.tsx`: Добавить временную кнопку "Superadmin Login", ведущую на `/admin/login`.
   **Критерии приемки:** Клик по кнопке на странице обычного входа успешно переводит на `/admin/login`. Попытка перейти на `/admin/superadmins` без входа редиректит на `/admin/login`.

## Этап 4: Экран авторизации суперадмина

**Цель:** Предоставить UI для входа в панель суперадмина.
**Задачи:**

1. `src/features/superadmin/pages/AdminLoginPage.tsx`: Разработать форму с полями Email и Пароль.
2. Привязать форму к экшену `loginAdmin`.
3. Реализовать редирект на `/admin/superadmins` при успешной авторизации.
   **Критерии приемки:** Можно успешно войти с учетными данными суперадмина. Токен сохраняется по ключу `chorApp.admin.accessToken`. UI корректно отображает ошибки входа (неверный пароль).

---

## Этап 5: Управление профилем (Self-management)

**Цель:** Реализовать управление собственными данными суперадмина (требование ADR 0011).
**Задачи:**

1. `src/features/superadmin/pages/AdminProfilePage.tsx`:
   - Блок изменения основной информации (имя, почта), отправляющий `PATCH /admin/me`.
   - Блок изменения пароля, отправляющий `POST /admin/me/change-password`.
2. Интеграция с извлеченным `error.code` для обработки конфликтов (например, `SUPERADMIN_EMAIL_TAKEN`).
   **Критерии приемки:** Суперадмин может изменить свои учетные данные и пароль.

---

## Этап 6: Управление списком суперадминов (CRUD)

**Цель:** Завершить возможности управления суперадминами.
**Задачи:**

1. `src/features/superadmin/pages/SuperadminsListPage.tsx`: Вывод таблицы со списком суперадминов (запрос `GET /admin/superadmins`).
2. Добавить модальное окно и логику создания (`POST /admin/superadmins`).
3. Добавить модальное окно и логику редактирования (`PATCH /admin/superadmins/:id`).
4. Добавить логику удаления (`DELETE /admin/superadmins/:id`) с подтверждением и блокировкой удаления самого себя (обработка кода ошибки `SUPERADMIN_LAST_REMAINING`).
   **Критерии приемки:** Полный цикл CRUD для суперадминов работает через интерфейс. Пользовательский интерфейс информирует об успешных операциях и ошибках.
