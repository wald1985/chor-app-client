# Экран «Verwaltung» (People): клиент

**Основание:** OpenSpec `add-people` (`../chor-app-docs/openspec/changes/add-people/`), серверный модуль `chor-app-server/src/people/`.
**Статус:** экран реализован (2026-10-12). Работа с живым сервером не проверялась: на момент написания миграция `people` не применена, e2e сервера не запускались.

## Что это

Вкладка `verwaltung` («Personen verwalten») показывает людей активного хора — пианистов и дирижёров. Один человек (`Person`) может иметь обе роли. `Person` не связан с аккаунтом `User`: гость без логина тоже может быть в списке.

## Как работает

- **Активный хор** — первое членство (`useActiveCommunity`), права берутся из `memberships[].permissions`.
- Просмотр доступен любому члену хора. Кнопки «Person hinzufügen», «Bearbeiten», «Archivieren»/«Wiederherstellen» видны только при `PEOPLE_MANAGE`; без права показывается пояснение. Сервер проверяет право в любом случае.
- Все люди хора (включая архивных) загружаются **одним запросом** (`includeArchived=true`), фильтры работают на клиенте: роль (Klavierspieler / Dirigent; человек с двумя ролями попадает в оба фильтра) и переключатель «Archivierte Personen anzeigen». Сортировка по имени без учёта регистра.
- **Форма** (модалка): имя и роли-чекбоксы. «Speichern» доступно, только если имя не пустое и выбрана хотя бы одна роль. Редактировать можно имя и роли, архивных — нельзя.
- **Удаления нет:** «Archivieren» скрывает человека из списка по умолчанию, «Wiederherstellen» возвращает. Операции идемпотентны.
- **Ошибки сервера** переводятся на немецкий (`utils/personLabels.ts`): дубль имени (`PERSON_NAME_TAKEN`; если держатель имени в архиве, в форме появляется кнопка «Archivierte Person wiederherstellen» — один клик восстанавливает его по `existingPersonId` из ответа 409, форма закрывается; восстановленный человек сохраняет прежние роли), правка архивной персоны, нет прав, не найдено.

## Код

`src/features/people/`: `types/`, `api/peopleApi.ts` (list/create/update/archive/restore), `hooks/usePeople.ts` (TanStack Query, ключ `["people", communityId, ...]`, инвалидация после записи), `components/PersonFormModal.tsx`, `pages/PeoplePage.tsx`, `utils/personLabels.ts`. Маршрут подключён в `App.tsx` вместо заглушки.

Хуки `useActiveCommunity` и `useCommunityPermission` перенесены в `src/features/auth/hooks/`, так как их используют и репертуар, и People.

## Тесты

Vitest + RTL: API-клиент, форма (валидация, предзаполнение, ошибка), страница (список и сортировка, фильтры, режим только для чтения, создание, конфликт имени, правка, архив и восстановление, ошибка загрузки, пользователь без хора). Проверки `type-check`, `lint`, `format:check`, `build` проходят.

## Не сделано

- Проверка на живом сервере после применения миграции.
- Выбор человека в формах Vortrag и Chorprobe (будущие возможности №6, №7) — потребуется фильтр по роли и показ только активных.
- Метка раздела: в UI используется «Personen», окончательное решение «Personen» или «Mitwirkende» остаётся за продуктом.
